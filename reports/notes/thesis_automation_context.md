# 共享文件监视自动任务上下文

- 项目：`GP-MMEA-TL`
- 文件用途：给自动任务/新线程提供“只监视共享文件、不直接修改论文”的稳定上下文
- 最近更新：`2026-03-14`

## 1. 自动任务的唯一职责

自动任务只负责：

1. 监视 `reports/notes/thread_sync_shared.md` 是否被项目优化线程更新
2. 读取新增内容并判断是否存在值得论文线程吸收的结果
3. 输出简短提醒或摘要，提示“论文线程需要处理什么”

自动任务**不负责**：

1. 不直接修改 `reports/thesis/本科毕业论文初稿_v1.md`
2. 不直接修改论文中的摘要、章节、结论或图表
3. 不代替论文线程写正文
4. 不在没有明确要求时重跑正式实验

## 2. 当前线程分工

当前分工必须严格保持：

1. 项目优化线程：
   - 补实验
   - 补证据
   - 更新共享文件
2. 自动任务：
   - 只监视共享文件是否有新回填
   - 只做提醒与摘要
3. 论文写作线程：
   - 读取共享文件最新内容
   - 决定如何吸收到论文
   - 真正修改论文与写作文件

## 3. 自动任务每次运行时必须读取的文件

1. `reports/notes/thread_sync_shared.md`
2. `reports/notes/thesis_automation_context.md`

如需判断论文是否可能需要更新，可只读：

3. `reports/thesis/本科毕业论文初稿_v1.md`

但即便读取论文，也只是为了判断“是否值得提醒”，不是为了直接改写论文。

## 4. 自动任务应如何判断“有新增”

优先关注共享文件中以下区域是否出现新的增量内容：

1. `4. 线程A -> 线程B：本轮/下轮回填区`
2. 其中新增的：
   - 正式实验结果
   - 新的汇总表/图表
   - 新的局限性说明
   - 新的可直接入文段落
3. 如果只有“基础能力已接入”“脚本已准备好”“dry-run 已通过”，但没有正式结果，则只提醒，不视为论文必须立刻改写

## 5. 自动任务的输出目标

自动任务输出应尽量短，重点回答：

1. 共享文件是否有新更新
2. 更新属于哪一类：
   - 强证据
   - 一般补充
   - 仅能力接入/暂不能入文
3. 论文线程下一步最值得处理的是什么

推荐输出风格：

- “共享文件有更新：新增了最小版 GPU 峰值显存结果，可回填第四章效率分析。”
- “共享文件有更新：仅新增 H3 脚本和 dry-run 记录，暂不建议改写论文正文。”
- “共享文件无实质更新，论文线程暂不需要动作。”

## 6. 自动任务必须遵守的边界

1. 不要自行把共享文件增量写进论文
2. 不要把尚未完成的 `H3` 或 GPU 补测说成已完成结果
3. 不要改动论文主结论边界
4. 只做“监视 + 提醒”，不做“写作替代”

## 7. 当前论文线程最关心的结果

自动任务如果看到以下内容出现正式结果，应优先提醒：

1. 最小版 `H3` 缺失模态压力测试正式结果
2. 最小版 GPU 峰值显存正式补测结果
3. 条件允许时扩展到 `8` 个案例的正式材料
4. 额外 baseline 的正式判断或论文可用局限性表述

## 8. 当前最重要的提醒口径

自动任务只需要服务于论文线程，不需要代替论文线程得出最终文字结论。

因此最稳妥的行为是：

1. 发现更新
2. 读懂更新
3. 告诉论文线程“这里值得吸收”
4. 停止在提醒层面
